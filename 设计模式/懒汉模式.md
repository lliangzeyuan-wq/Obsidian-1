### 为什么饿汉模式会有线程安全问题
#### 问题根源：竞态条件（Race Condition）

看这段代码：
```cpp
static TaskQueue* getInstance() {
    if (m_taskQ == nullptr) {      // 检查
        m_taskQ = new TaskQueue;    // 创建
    }
    return m_taskQ;
}
```

在单线程下，这段代码没问题：

- 第一次调用：`m_taskQ` 是 `nullptr`，进入 `if`，创建对象并返回。
- 后续调用：直接返回已创建的指针。

但在多线程下，就会出现问题：

1. **线程 A** 调用 `getInstance()`，检查 `m_taskQ == nullptr`，条件成立，准备进入 `if` 块。
2. 此时线程 A 的时间片用完，操作系统切换到 **线程 B**。
3. **线程 B** 也调用 `getInstance()`，同样检查 `m_taskQ == nullptr`，条件依然成立，于是它成功创建了对象并返回。
4. 线程 A 恢复执行，继续执行 `m_taskQ = new TaskQueue;`，又创建了一个新的对象，覆盖了之前的指针。

结果就是：

- 系统中存在了 **两个** `TaskQueue` 实例。
- 线程 A 和线程 B 拿到的是不同的指针，破坏了单例的唯一性。
- 还会造成内存泄漏，因为第一个对象的指针丢失了，无法被释放。






- 执行加锁操作，但是执行效率太低了（为什么效率低？因为：无论单例对象是否已经被创建，每次调用`getInstance()`都会先加锁再解锁。
```cpp
public:
	TaskQueue(const TaskQueue& t) = delete;
	TaskQueue& operator=(const TaskQueue& t) = delete;
	static TaskQueue* getInstance() {
		m_mutex.lock();
		if (m_taskQ == nullptr) {
			m_taskQ = new TaskQueue;
		}
		m_mutex.unlock();
		return m_taskQ;
	}
```

- **典型错误**。问题：当多个线程同时通过第一次 `if (m_taskQ == nullptr)` 检查后，都会尝试加锁。第一个线程创建完对象并解锁后，后续等待的线程会继续执行 `new TaskQueue`，导致**单例被多次创建**，破坏了单例的唯一性。
```cpp
public:
	static TaskQueue* getInstance() {
		if (m_taskQ == nullptr) {
			m_mutex.lock();
			m_taskQ = new TaskQueue;
			m_mutex.unlock();
		}
		return m_taskQ;
	}
```


- **双重检查锁定**：提高效率，保证线程安全。
```cpp
public:
	static TaskQueue* getInstance() {
		if (m_taskQ == nullptr) {
			m_mutex.lock();
			if (m_taskQ == nullptr) {
				m_taskQ = new TaskQueue;
			}
			m_mutex.unlock();
		}
		return m_taskQ;
	}
```

### 双重检查锁定的问题
假设有两个线程A、B，当线程A 执行到第 8 行时在线程A中 TaskQueue 实例对象 被创建，并赋值给 m_taskQ。

```cpp
static TaskQueue* getInstance()
{
    if (m_taskQ == nullptr)
    {
        m_mutex.lock();
        if (m_taskQ == nullptr)
        {
            m_taskQ = new TaskQueue;
        }
        m_mutex.unlock();
    }
    return m_taskQ;
}
```
但是实际上 m_taskQ = new TaskQueue; 在执行过程中对应的机器指令可能会被重新排序。正常过程如下：

第一步：分配内存用于保存 TaskQueue 对象。

第二步：在分配的内存中构造一个 TaskQueue 对象（初始化内存）。

第三步：使用 m_taskQ 指针指向分配的内存。

但是被重新排序以后执行顺序可能会变成这样：

第一步：分配内存用于保存 TaskQueue 对象。

第二步：使用 m_taskQ 指针指向分配的内存。

第三步：在分配的内存中构造一个 TaskQueue 对象（初始化内存）。

这样重排序并不影响单线程的执行结果，但是在多线程中就会出问题。如果线程A按照第二种顺序执行机器指令，执行完前两步之后失去CPU时间片被挂起了，此时线程B在第3行处进行指针判断的时候m_taskQ 指针是不为空的，但这个指针指向的内存却没有被初始化，最后线程 B 使用了一个没有被初始化的队列对象就出问题了（出现这种情况是概率问题，需要反复的大量测试问题才可能会出现）。
