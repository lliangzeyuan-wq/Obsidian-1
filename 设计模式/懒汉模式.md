- 什么时候使用这个静态成员变量，什么时候实例化
```cpp
#include<iostream>

class TaskQueue {
public:
	TaskQueue(const TaskQueue& t) = delete;
	TaskQueue& operator=(const TaskQueue& t) = delete;

			m_taskQ = new TaskQueue;
		}
		return m_taskQ;
	}

		cout << "我是单例对象的一个成员函数..." << endl;

	//TaskQueue() {};

	TaskQueue() = default;
	//TaskQueue(const TaskQueue& t) = default;
	//TaskQueue& operator=(const TaskQueue& t) = default;

	//只能通过类名访问静态属性或方法

	TaskQueue* taskQ = TaskQueue::getInstance();
	taskQ->print();
```

### 为什么饿汉模式会有线程安全问题
#### 问题根源：竞态条件（Race Condition）

看这段代码：
```cpp
static TaskQueue* getInstance() {
    if (m_taskQ == nullptr) {      // 检查
        m_taskQ = new TaskQueue;    // 创建
    }
    return m_taskQ;
}
```

在单线程下，这段代码没问题：

- 第一次调用：`m_taskQ` 是 `nullptr`，进入 `if`，创建对象并返回。
- 后续调用：直接返回已创建的指针。

但在多线程下，就会出现问题：

1. **线程 A** 调用 `getInstance()`，检查 `m_taskQ == nullptr`，条件成立，准备进入 `if` 块。
2. 此时线程 A 的时间片用完，操作系统切换到 **线程 B**。
3. **线程 B** 也调用 `getInstance()`，同样检查 `m_taskQ == nullptr`，条件依然成立，于是它成功创建了对象并返回。
4. 线程 A 恢复执行，继续执行 `m_taskQ = new TaskQueue;`，又创建了一个新的对象，覆盖了之前的指针。

结果就是：

- 系统中存在了 **两个** `TaskQueue` 实例。
- 线程 A 和线程 B 拿到的是不同的指针，破坏了单例的唯一性。
- 还会造成内存泄漏，因为第一个对象的指针丢失了，无法被释放。






- 执行加锁操作，但是执行效率太低了（为什么效率低？因为：无论单例对象是否已经被创建，每次调用`getInstance()`都会先加锁再解锁。
```cpp
public:
	TaskQueue(const TaskQueue& t) = delete;
	TaskQueue& operator=(const TaskQueue& t) = delete;
	static TaskQueue* getInstance() {
		m_mutex.lock();
		if (m_taskQ == nullptr) {
			m_taskQ = new TaskQueue;
		}
		m_mutex.unlock();
		return m_taskQ;
	}
```

```cpp
#include<iostream>
using namespace std;
#include<mutex>

class TaskQueue {
public:
	TaskQueue(const TaskQueue& t) = delete;
	TaskQueue& operator=(const TaskQueue& t) = delete;
	static TaskQueue* getInstance() {
		m_mutex.lock();
		if (m_taskQ == nullptr) {
			m_taskQ = new TaskQueue;
		}
		m_mutex.unlock();
		return m_taskQ;
	}
	void print() {
		cout << "我是单例对象的一个成员函数..." << endl;
	}
private:
	//TaskQueue() {};
	//TaskQueue(const TaskQueue& t) {};
	//TaskQueue& operator=(const TaskQueue& t) {};
	
	TaskQueue() = default;
	//TaskQueue(const TaskQueue& t) = default;
	//TaskQueue& operator=(const TaskQueue& t) = default;

	//只能通过类名访问静态属性或方法
	static TaskQueue* m_taskQ;
	static mutex m_mutex;
};
TaskQueue* TaskQueue::m_taskQ = nullptr;

int main() {
	TaskQueue* taskQ = TaskQueue::getInstance();
	taskQ->print();
	return 0;
}
```



- **典型错误**。问题：当多个线程同时通过第一次 `if (m_taskQ == nullptr)` 检查后，都会尝试加锁。第一个线程创建完对象并解锁后，后续等待的线程会继续执行 `new TaskQueue`，导致**单例被多次创建**，破坏了单例的唯一性。
```cpp
public:
	static TaskQueue* getInstance() {
		if (m_taskQ == nullptr) {
			m_mutex.lock();
			m_taskQ = new TaskQueue;
			m_mutex.unlock();
		}
		return m_taskQ;
	}
```


- 双重检查锁定：提高效率，保证线程安全。
```cpp
public:
	static TaskQueue* getInstance() {
		if (m_taskQ == nullptr) {
			m_mutex.lock();
			if (m_taskQ == nullptr) {
				m_taskQ = new TaskQueue;
			}
			m_mutex.unlock();
		}
		return m_taskQ;
	}
```
