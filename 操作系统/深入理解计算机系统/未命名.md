# 固定大小整数类型笔记（整理自 CSAPP）

---

## 一、背景：为什么需要固定大小的整数类型？

C 语言的基础类型（`int/long`）存在平台差异：

- `long` 在 32 位机器上是 4 字节，在 64 位机器上是 8 字节。
- 这会导致跨平台程序的可移植性问题，尤其是在网络通信、协议处理中，必须保证数据类型的大小严格一致。

C 语言标准只规定了基础类型的**最小范围**，而不是固定大小。为了解决这个问题，C99 标准引入了 `<stdint.h>` 头文件，定义了**固定宽度整数类型**。

---

## 二、核心：`<stdint.h>` 中的固定大小类型

### 1. 类型定义

这些类型的命名规则是：`intN_t`（有符号）和 `uintN_t`（无符号），其中 `N` 代表位数，常见值为 8、16、32、64。

- `int8_t`：8 位有符号整数
- `uint16_t`：16 位无符号整数
- `int32_t`：32 位有符号整数
- `uint64_t`：64 位无符号整数

它们的大小在任何平台上都是固定的，解决了跨平台兼容性问题。

### 2. 边界值宏定义

同时，`stdint.h` 还定义了这些类型的边界值宏：

- `INTN_MIN`：`intN_t` 的最小值
- `INTN_MAX`：`intN_t` 的最大值
- `UINTN_MAX`：`uintN_t` 的最大值

---

## 三、关键问题：`printf` 如何打印这些类型？

直接用 `%d` 或 `%u` 打印固定大小类型是不可移植的，因为它们在不同平台上对应的格式符可能不同。

C 标准提供了 `<inttypes.h>` 头文件中的宏，来解决这个问题：

- `PRIdN`：对应 `intN_t` 的十进制格式符
- `PRIuN`：对应 `uintN_t` 的十进制格式符

### 例子

c

运行

```
#include <stdio.h>
#include <stdint.h>
#include <inttypes.h>

int main() {
    int32_t x = 100;
    uint64_t y = 200;

    printf("x = %" PRId32 ", y = %" PRIu64 "\n", x, y);
    return 0;
}
```

- 在 32 位平台上，`PRId32` 会被展开为 `"d"`，`PRIu64` 会被展开为 `"llu"`。
- 在 64 位平台上，`PRId32` 会被展开为 `"d"`，`PRIu64` 会被展开为 `"lu"`。
- 预处理器会将这些相邻的字符串常量自动拼接，最终生成正确的格式字符串。

---

## 四、对比：Java 的整数类型

Java 为了保证跨平台一致性，直接规定了整数类型的固定大小和表示方式：

- 强制采用补码表示。
- `byte`（8 位）、`short`（16 位）、`int`（32 位）、`long`（64 位）的大小在所有平台上固定不变。
- 这保证了 Java 程序在任何机器上的行为完全一致。
