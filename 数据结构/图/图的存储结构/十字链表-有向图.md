# 有向图的十字链表存储结构笔记

---

## 一、核心定义

十字链表是**有向图**的一种链式存储结构，它同时解决了邻接表无法高效查询入度、逆邻接表无法高效查询出度的问题，能同时支持快速获取顶点的入度和出度。

---

## 二、数据结构定义

### 1. 顶点结构（顶点节点）

cpp

运行

```
struct VNode {
    // 顶点自身信息（如编号、名称）
    string data;
    // 指向该顶点的入边链表的第一个节点
    ArcNode *firstin;
    // 指向该顶点的出边链表的第一个节点
    ArcNode *firstout;
};
```

### 2. 边（弧）表节点结构（弧节点）

cpp

运行

```
struct ArcNode {
    // 弧的起点在顶点数组中的下标（tail → head）
    int tailvex;
    // 弧的终点在顶点数组中的下标
    int headvex;
    // 入边表指针：指向**终点相同**的下一条边
    ArcNode *hlink;
    // 出边表指针：指向**起点相同**的下一条边
    ArcNode *tlink;
    // （可选）边的权值
    int weight;
};
```

---

## 三、核心逻辑说明

十字链表的核心是 **“十字交叉” 的双链表结构 **：

1. **出边链**：以顶点的 `firstout` 为头，通过 `tlink` 指针串联所有从该顶点出发的边，构成出边链表，可快速统计出度。
2. **入边链**：以顶点的 `firstin` 为头，通过 `hlink` 指针串联所有指向该顶点的边，构成入边链表，可快速统计入度。
3. 每条边节点同时属于两条链：它既是起点的出边链成员，也是终点的入边链成员，因此一条边只需存储一次，空间利用率高。

---

## 四、示例解析

以图中示例的有向图为例：

- 顶点集合：`v1(0), v2(1), v3(2), v4(3)`
- 边集合：`(0,1)、(0,2)、(2,0)、(2,3)、(3,0)、(3,1)、(3,2)`

十字链表的构建逻辑：

1. 顶点数组中每个元素包含 `data`、`firstin`、`firstout` 三个字段。
2. 边节点 `(0,1)`：`tailvex=0`、`headvex=1`，`tlink` 指向 `(0,2)`（起点同为 0 的下一条边），`hlink` 指向其他终点为 1 的边（如 `(3,1)`）。
3. 顶点 `v1(0)` 的 `firstout` 指向 `(0,1)`，顶点 `v2(1)` 的 `firstin` 指向 `(0,1)`，以此实现边节点同时属于两条链。

---

## 五、优缺点对比

表格

|优点|缺点|
|---|---|
|同时支持快速查询入度和出度，无需额外遍历或构建逆邻接表|结构相对复杂，实现和调试成本比邻接表高|
|一条边仅存储一次，空间复杂度为 \(O(V+E)\)，和邻接表相同|不适合无向图存储（无向图通常用邻接多重表）|
|边的插入、删除操作可同时更新入边链和出边链，效率较高||

---

## 补充说明

十字链表是有向图的专用存储结构，核心解决了邻接表 “出度易、入度难” 的痛点，适合需要频繁查询顶点入度和出度的场景（如拓扑排序、关键路径算法）。
