## 二、“啃代码” 怎么啃？给你一个清晰的路线图

你可以按照下面的顺序，结合日志和代码逐模块拆解：

### 1. 先从入口和核心流程入手（`tcp_server.cpp`）

- 重点看 `start()` 函数：服务器启动流程、监听 socket 创建、线程池初始化、事件循环启动。
- 对应日志里的：`create one acceptor`、`bind, port is 8889`、`create thread pool`。
- 面试能讲：服务器从启动到监听的完整流程，主 Reactor 负责接收连接的逻辑。

### 2. 再啃事件循环（`event_loop.cpp` + `epoll.cpp`）

- 重点看 `EventLoop::loop()` 函数：epoll 事件循环的核心逻辑，怎么监听事件、怎么执行回调。
- 对应日志里的：`epoll add, fd is X, event is 1`、`execute read cb`。
- 面试能讲：epoll 水平 / 边缘触发模式、事件循环的非阻塞设计、回调函数的注册与执行。

### 3. 然后是连接管理（`tcp_conn.cpp`）

- 重点看连接的创建、读 / 写事件处理、连接销毁逻辑，尤其是 `connected`、`handle_read`、`handle_write` 函数。
- 对应日志里的：`one connected`、`recv message`、`add read to poller`。
- 面试能讲：TCP 连接的生命周期、数据读写流程、怎么处理半连接 / 异常断开。

### 4. 最后啃线程池和内存管理（`thread_pool.cpp` + `mem_pool.cpp`）

- 重点看线程池的任务队列、任务提交、工作线程逻辑，以及内存池的分配 / 释放。
- 结合你遇到的 `double free` 崩溃，重点排查线程安全问题。
- 面试能讲：多线程池的设计、任务队列的线程安全、内存池优化与踩坑。

## 三、“面试话术” 怎么准备？给你几个高频考点的准备方向

1. **Reactor 模型**：主从 Reactor 模型的设计思路，主 Reactor 和从 Reactor 分别负责什么，为什么要这样设计？
2. **epoll 事件循环**：epoll 的三种工作模式，你的服务器用的是哪种？为什么？epoll 惊群问题你是怎么处理的？
3. **多线程池**：线程池的任务队列怎么实现？任务提交和消费怎么保证线程安全？有没有用锁？
4. **压测与优化**：你压测的结果是多少？遇到了什么问题（比如你这次的内存错误）？怎么定位和解决的？

## 四、给你一个建议：边啃边写项目文档

每啃完一个模块，就用自己的话写一段笔记，包括：

- 这个模块的核心功能
- 关键代码逻辑
- 你踩过的坑和解决方法

这些笔记，就是你面试时的 “标准答案”，比临时背知识点要管用得多。
