## 2. epoll 事件多路复用（重中之重，项目核心）

这是这套高并发服务器的**灵魂**，`EventLoop` 完全基于 epoll 封装。

### 核心知识点

1. epoll 三大函数：`epoll_create` / `epoll_ctl` / `epoll_wait`
2. 两种触发模式：**水平触发 (LT)**、**边缘触发 (ET)** 区别与使用场景
3. epoll 监听事件：`EPOLLIN`(读事件)、`EPOLLOUT`(写事件)
4. epoll + 非阻塞 IO 组合用法

### 对应你代码里的模块

`EventLoop`、`epoll.cpp`，整个事件循环依赖它。

### 必搞懂问题（面试高频）

- epoll 为什么比 select/poll 高效？
- 边缘触发下为什么必须循环读写？

## 3. Linux 信号处理

代码构造函数里直接用到，线上服务必备。

### 核心知识点

1. `signal()` 函数用法、信号回调
2. 两个关键信号（你代码里显式忽略）：
    
    - `SIGPIPE`：向**已断开的 TCP 连接**写数据触发，不忽略会直接进程退出
    - `SIGHUP`：终端会话关闭触发
    
3. 服务端为什么要忽略这两个信号？

### 对应代码

cpp

运行

```
signal(SIGHUP, SIG_IGN);
signal(SIGPIPE, SIG_IGN);
```

# 二、第二梯队：架构思想（读懂整体设计、应对面试，读完代码再补）

## 1. Reactor 反应堆模型（项目整体架构）

你这个是标准 **主从 Reactor（多 Reactor）**，面试必考。

### 核心知识点

1. 单 Reactor 模型流程、优缺点
2. **主从 Reactor 分工**（你项目的架构）：
    
    - 主 Reactor（`ts_acceptor_loop`）：只负责 `listen` + `accept` 新连接
    - 从 Reactor（多个`EventLoop`）：负责已建立连接的读写事件
    
3. 负载均衡：轮询 (Round-Robin) 分配连接（对应 `get_next_loop()` 函数）
4. `one loop per thread` 设计思想：一个线程绑定一个事件循环

### 对应代码

整个 `TcpServer` 类就是主从 Reactor 的管理者。

---

## 2. 事件驱动编程思想

### 核心知识点

1. 什么是**事件驱动**：不主动轮询，等待事件到来再执行回调
2. 回调函数的设计思路（项目中所有读写、连接事件都是回调）
3. 事件循环 `loop()` 的死循环逻辑

### 对应代码

`EventLoop::loop()` 主循环
