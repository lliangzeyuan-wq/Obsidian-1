## 一、整体概览

32 位 Linux 系统中，每个进程都拥有独立的 **4GB 虚拟地址空间**，被分为两大部分：

- **0 ~ 3GB：用户空间（User Space）**
    
    存放进程自己的代码、数据、栈、堆、动态库等，进程的用户态代码只能访问这里。
- **3GB ~ 4GB：内核空间（Kernel Space）**
    
    存放操作系统内核代码和数据，进程的用户态代码无法直接访问，只有内核态（系统调用时）才能访问。

## 二、用户空间（0~3GB）从低到高详解

### 1. `.text` 段（代码段）

- 地址从 `0` 开始，存放程序的机器指令（可执行代码）。
- 权限：**只读 + 可执行**，防止被意外修改。
- 比如你写的 `main()` 函数、其他函数的编译结果，都在这里。

### 2. `.rodata` 段（只读数据段）

- 存放程序里的只读常量，比如字符串常量 `const char* str = "hello"`、`#define` 宏定义的常量。
- 权限：**只读**，不能修改。

### 3. `.data` 段（数据段）

- 存放程序里**已初始化的全局变量和静态变量**，比如 `int g_val = 10;`。
- 权限：**可读可写**。

### 4. `.bss` 段（BSS 段）

- 存放程序里**未初始化的全局变量和静态变量**，比如 `int g_val;`。
- 特点：不占用可执行文件的磁盘空间，加载时才分配内存并初始化为 0。
- 权限：**可读可写**。

### 5. `heap`（堆）

- 存放程序运行时动态分配的内存，比如 `malloc()` / `new` 申请的空间。
- 地址方向：**向上增长**（从低地址往高地址扩展）。
- 由程序员手动管理（申请 / 释放）。

### 6. `.so 加载位置`（共享库 / 动态库）

- 存放进程加载的动态库（`.so` 文件），比如 `libc.so`、你自己写的 `libmymath.so`。
- 动态库是位置无关代码（PIC），运行时会被加载到这个区域，然后通过 ** 地址回填（重定位）** 修正符号地址。

### 7. `stack`（栈）

- 存放函数调用栈帧：局部变量、函数参数、返回地址、寄存器上下文等。
- 地址方向：**向下增长**（从高地址往低地址扩展）。
- 特点：自动管理，函数调用时分配，返回时自动释放。

### 8. 环境变量 + `main` 参数

- 位于用户空间的最顶端，靠近 3GB 边界。
- 存放进程的环境变量（比如 `PATH`、`LD_LIBRARY_PATH`）和命令行参数（`argv`）。

## 三、和你之前学的动态库 / 地址回填有什么关系？

1. 动态库 `.so` 会被加载到 `heap` 和 `stack` 之间的共享库区域。
2. 编译时，程序只知道动态库函数的**相对偏移**，不知道它最终会被加载到这个区域的哪个地址。
3. 运行时，动态链接器把 `.so` 加载到虚拟地址空间后，会通过**地址回填（重定位）**，把程序中调用动态库函数的指令，修正为该函数在虚拟地址空间中的真实地址。
