# 我用**最简单、最直白、从头到尾**的方式，一次性把 `gcc` 讲透！

你现在学的是 **Linux C 编程 + Makefile**，我保证你听完彻底懂，再也不懵！

---

# 0. 一句话总纲（先背这个）

**gcc = 把 .c 源代码 → 变成 可运行程序 的编译器**

编译过程一共 **4 步**，但我们平时只用 **2 种用法**：

1. **一步到位**（新手常用）
2. **分步编译**（企业 / Makefile 用）

---

# 1. 最基础用法（一步到位）

bash

运行

```
gcc hello.c -o hello
```

### 意思：

把 `hello.c` 源代码 **直接编译 + 链接**，生成可执行程序 `hello`

### 运行：

bash

运行

```
./hello
```

### 最简单记忆：

plaintext

```
gcc 源文件 -o 可执行文件
```

---

# 2. 你最困惑的：`-c` 到底干嘛？

bash

运行

```
gcc -c hello.c
```

### `-c` = **只编译，不链接**

### 结果：生成 `hello.o`（目标文件）

`.o` 文件 **不能运行**，它是中间文件。

---

# 3. 第二步：把 `.o` 变成可执行文件

bash

运行

```
gcc hello.o -o hello
```

### 这一步叫：**链接**

把 `.o` 和系统库绑在一起 → 生成最终可运行程序

---

# 4. 完整流程（最关键）

## 写法 1：一步到底（新手）

bash

运行

```
gcc hello.c -o hello
```

编译 + 链接 一次完成 ✅

## 写法 2：分两步（企业 / Makefile）

bash

运行

```
gcc -c hello.c   # 第一步：编译 → 生成 hello.o
gcc hello.o -o hello  # 第二步：链接 → 生成 hello
```

---

# 5. 为什么要分两步？（重点！）

因为 **大型项目有 100 个 .c 文件**

你只改了一个，不需要全部重新编译！

只需要：

plaintext

```
gcc -c 你改的那个文件.c
gcc 所有.o文件 -o 最终程序
```

**Makefile 就是干这个的！**

---

# 6. 最常用的几个参数（必须记）

plaintext

```
gcc -c      → 只编译，生成 .o
gcc -o      → 指定输出文件名
gcc -Wall   → 显示所有警告（企业必备）
gcc -g      → 生成调试信息（gdb用）
```

---

# 7. 终极总结（你一定能记住）

## 1）`gcc 文件名.c`

直接生成 `a.out`（默认可执行文件）

## 2）`gcc 文件名.c -o 程序名`

编译 + 链接 → 生成可执行程序

## 3）`gcc -c 文件名.c`

只编译 → 生成 `.o` 文件（不能运行）

## 4）`gcc 文件名.o -o 程序名`

只链接 → 生成可执行程序

---

plaintext

```
-o 指定输出名字
不带 c，直接生成可执行程序
```
