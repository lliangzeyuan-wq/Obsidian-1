# 动态库 「动态绑定」 极简大白话 + Markdown 整理

## 一、先分清两个关键名词

1. **静态绑定（早绑定）**
    
    编译链接阶段，就把库函数的**地址 / 机器码**直接拷进程序里。
    
    对应：静态库 `.a`
    
2. **动态绑定（晚绑定）**
    
    编译时**不拷贝函数实现、不填真实地址**，
    
    等到 **程序运行起来那一刻**，才临时去找动态库、找函数地址、绑定调用。
    
    对应：动态库 `.so` / `.dll`
    

---

## 二、动态绑定 核心原理

1. 编译时
    
    - 只做**函数声明检查**，不找函数实现
    - 不把库代码合并进可执行文件
    - 只记录：「我要调用 xxx 函数，后续运行再找」
    
2. 程序运行时（动态绑定发生在这里）
    
    1. 操作系统加载可执行文件
    2. 动态链接器 (`ld-linux`) 自动加载需要的 `.so` 动态库
    3. 在库里找到目标函数（`add/sub`…）
    4. **临时回填函数真实内存地址**
    5. 程序才正常调用函数
    

> 核心：**编译只登记，运行才绑定**

---

## 三、动态绑定 两大特点

### 1. 延迟绑定（晚绑定）

- 函数地址**运行时才解析**
- 编译、链接阶段都不知道函数真实地址

### 2. 共享内存

- 多个程序用同一个 `.so`
- 内存里**只加载一份库代码**，节省内存

---

## 四、对比：静态绑定 vs 动态绑定

表格

|对比|静态绑定（静态库）|动态绑定（动态库）|
|---|---|---|
|绑定时机|链接阶段（早早绑死）|运行阶段（临时绑定）|
|库文件|`.a`|`.so` / `.dll`|
|体积|可执行文件大（代码拷进去）|程序体积小|
|依赖|运行不需要原库|运行**必须有动态库**|
|更新|库更新，程序要重新编译|替换 `.so` 即可，不用重编|

## 五、补充：手动动态绑定（代码级）

Linux 下可以代码里手动控制动态绑定：

c

运行

```
dlopen()   // 打开动态库
dlsym()    // 手动获取函数地址（手动绑定）
dlclose()  // 关闭库
```

这是**程序员自己写代码完成动态绑定**，比系统自动动态绑定更灵活。

---

## 六、一句话背考点

**动态绑定 = 运行时才去找动态库、解析函数地址、完成调用绑定；

静态绑定 = 链接时直接把库代码合并进程序，提前绑死。**
