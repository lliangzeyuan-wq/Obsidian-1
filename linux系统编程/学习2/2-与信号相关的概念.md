## 一、信号的产生方式（5 种）

这是信号的来源，也是你后续写代码会经常遇到的场景：

1. **按键产生**
    
    终端上的快捷键，本质是内核给前台进程发信号：
    
    - `Ctrl + C`：发送 `SIGINT`（2 号信号，终止进程）
    - `Ctrl + Z`：发送 `SIGTSTP`（20 号信号，暂停进程）
    - `Ctrl + \`：发送 `SIGQUIT`（3 号信号，终止进程并生成 core 文件）
    
2. **系统调用产生**
    
    进程主动通过系统调用让内核发信号：
    
    - `kill()`：给指定进程 / 进程组发任意信号
    - `raise()`：给自己发信号（等价于 `kill(getpid(), sig)`）
    - `abort()`：给自己发 `SIGABRT` 信号，让进程异常终止
    
3. **软件条件产生**
    
    满足特定软件条件时，内核自动发信号：
    
    - `alarm()` 定时器超时 → 内核发 `SIGALRM`（14 号信号）
    - 管道写端关闭后，读端继续读 → 内核发 `SIGPIPE`（13 号信号）
    
4. **硬件异常产生**
    
    CPU 检测到硬件错误，内核给进程发信号：
    
    - 非法访问内存（段错误）→ `SIGSEGV`（11 号信号）
    - 除 0（浮点异常）→ `SIGFPE`（8 号信号）
    - 内存对齐错误 → `SIGBUS`（7 号信号）
    
5. **命令产生**
    
    终端命令行通过 `kill` 命令给进程发信号：
    
    - `kill -9 pid`：给进程 `pid` 发送 `SIGKILL`（9 号信号，强制杀死进程）
    - `kill -USR1 pid`：给进程 `pid` 发送用户自定义信号 `SIGUSR1`（10 号信号）

## 二、信号的状态：递达、未决

信号从产生到被进程处理，中间有两个关键状态：

表格

|状态|含义|产生原因|
|:--|:--|:--|
|**递达**|信号已经被进程接收并处理（执行了默认动作 / 忽略 / 用户自定义函数）|信号被进程处理完成|
|**未决**|信号已经产生，但还没被进程处理，处于 “待处理” 状态|进程阻塞（屏蔽）了该信号，暂时不处理|

举个例子：

父进程屏蔽了 `SIGCHLD` 信号，此时子进程退出，内核会给父进程发 `SIGCHLD`，但因为信号被屏蔽，这个信号就处于**未决状态**；当父进程解除屏蔽后，信号才会变成**递达状态**，被父进程处理。

## 三、信号的处理方式（3 种）

进程收到递达的信号后，有三种处理方式：

1. **执行默认动作**
    
    每个信号都有内核预设的默认处理方式，比如：
    
    - `SIGINT`（Ctrl+C）默认动作：终止进程
    - `SIGKILL` 信号的默认动作：强制终止进程，且**不能被修改**
    - `SIGCHLD` 默认动作：忽略（这也是为什么僵尸进程会产生的原因之一）
    
2. **忽略（丢弃）信号**
    
    进程收到信号后，直接当作没收到，不做任何处理。
    
    注意：`SIGKILL` 和 `SIGSTOP` 信号**不能被忽略**，也不能被捕捉。
    
3. **捕捉（调用用户处理函数）**
    
    进程提前注册一个用户自定义的处理函数，当收到信号时，内核会暂停当前进程，跳转到用户写的函数里执行，执行完再回到原来的代码继续运行。
    
    你笔记里的 `SIGCHLD` 回收子进程，就是用的这种方式：注册一个信号处理函数，里面调用 `waitpid()` 回收子进程。

## 四、内核中的信号相关结构（PCB 里的两个集合）

Linux 内核的进程控制块 `task_struct`（也就是 PCB）里，包含了两个和信号相关的集合：

1. **阻塞信号集（信号屏蔽字）**
    
    - 本质：一个位图，用来标记哪些信号是被进程 “屏蔽” 的
    - 作用：如果某个信号在阻塞信号集里，那么当进程收到这个信号时，会被放到**未决状态**，暂时不处理，直到进程解除对它的屏蔽
    - 注意：`SIGKILL` 和 `SIGSTOP` 不能被屏蔽
    
2. **未决信号集**
    
    - 本质：也是一个位图，用来标记哪些信号已经产生，但还没被进程处理（也就是处于未决状态）
    - 作用：内核用它来记录进程当前 “待处理” 的信号，当进程解除对某个信号的屏蔽后，内核会检查未决信号集，发现该信号存在，就会把它递达给进程处理
    

举个形象的例子：

- 阻塞信号集就像一个 “黑名单”，在里面的信号，进程暂时不接
- 未决信号集就像一个 “待办清单”，收到的黑名单里的信号，先放到清单里，等解除屏蔽后再处理

## 五、本节的核心考点总结

1. 信号的 5 种产生方式：按键、系统调用、软件条件、硬件异常、命令
2. 信号的两种状态：递达（已处理）、未决（被屏蔽待处理）
3. 信号的三种处理方式：默认动作、忽略、捕捉
4. PCB 里的两个信号集：阻塞信号集（屏蔽）、未决信号集（待处理）
