# Linux 信号的 5 种默认处理动作
## 一、每个缩写的含义 & 对应英文

表格

|缩写|英文全称|含义|典型信号例子|
|:--|:--|:--|:--|
|**Term**|Terminate|终止进程|`SIGINT`、`SIGTERM`、`SIGKILL`|
|**Ign**|Ignore|忽略信号（收到不做任何处理）|`SIGCHLD`、`SIGURG`、`SIGWINCH`|
|**Core**|Core Dump|终止进程 + 生成 `core` 文件（崩溃快照）|`SIGSEGV`、`SIGFPE`、`SIGABRT`|
|**Stop**|Stop|暂停进程执行（进程进入停止状态）|`SIGSTOP`、`SIGTSTP`、`SIGTTIN`|
|**Cont**|Continue|恢复被暂停的进程，让它继续运行|`SIGCONT`|

---

## 二、逐个拆解（结合你之前学的信号）

1. **Term（终止进程）**
    
    最常见的默认动作，进程收到信号后直接退出。
    
    比如：按下`Ctrl+C`发送`SIGINT`，或者`kill`命令默认发送的`SIGTERM`，都会触发这个动作。
    
2. **Ign（忽略信号）**
    
    进程收到信号后，内核直接丢弃它，进程完全没反应。
    
    比如：子进程退出时给父进程发的`SIGCHLD`，默认就是被忽略的，父进程不会被打断。
    
3. **Core（终止 + 生成 core 文件）**
    
    比 Term 多了一步：进程崩溃时，把当时的内存、堆栈、寄存器全部保存成`core`文件，方便用`gdb`调试找 bug。
    
    比如：除 0 错误触发的`SIGFPE`、段错误触发的`SIGSEGV`，都会生成 core 文件。
    
4. **Stop（暂停进程）**
    
    进程收到信号后，会立刻停止执行，进入 “暂停状态”，CPU 不再给它分配时间片。
    
    比如：按下`Ctrl+Z`发送`SIGTSTP`，或者强制暂停的`SIGSTOP`，都会触发这个动作。
    
5. **Cont（继续运行）**
    
    专门用来恢复被`Stop`暂停的进程，让它从暂停的地方继续执行。
    
    比如：用`fg`/`bg`命令恢复后台暂停的进程，本质就是给进程发送`SIGCONT`信号。
    

---

## 三、补充两个关键细节

- 不是所有信号都能被修改动作：`SIGKILL`和`SIGSTOP`是特殊的，**不能被捕获、忽略或阻塞**，只能按默认动作执行（Term 和 Stop）。
- 你可以用`man 7 signal`查看每个信号对应的默认动作，和这张表是完全对应的。
