## 一、什么是环境变量？

环境变量就是**操作系统给进程传递的 “全局配置信息”**，本质是一串 `name=value` 格式的字符串，用来定义进程的运行环境。

它有 3 个核心特征：

1. **本质是字符串**：比如 `PATH=/bin:/usr/bin` 就是一个字符串。
2. **格式固定**：`变量名=值`（值里可以用冒号分隔多个路径）。
3. **描述进程环境**：进程可以读取这些变量，知道 “去哪里找命令、当前终端是什么类型、用户主目录在哪” 等信息。

---

## 二、环境变量怎么存储？

### 1. 底层存储形式

环境变量和命令行参数类似，存在一个 `char *environ[]` 数组里：

- 每个元素是一个指向 `name=value` 字符串的指针；
- 数组最后以 `NULL` 结尾（哨兵）。

### 2. 在进程地址空间的位置

它和命令行参数一起，放在**用户栈的上方（高地址区域）**，进程启动时由操作系统加载进去。

### 3. 怎么在 C 语言里使用？

如果要在代码里读取环境变量表，需要先声明：

c

运行

```

```

## 三、常见环境变量详解

下面是图里提到的几个核心环境变量，每个都给你讲清楚作用：

表格

|环境变量|作用|大白话场景|
|:--|:--|:--|
|**`PATH`**|可执行文件的搜索路径|为什么你敲 `ls` 不用写 `/bin/ls`？因为 `PATH` 里包含了 `/bin` 目录，系统会按顺序在这些目录里找命令。而 `./a.out` 要加 `./`，就是因为当前目录 `.` 不在 `PATH` 里。|
|**`SHELL`**|当前使用的 Shell 程序|一般是 `/bin/bash`，就是你敲命令的那个终端解释器。|
|**`TERM`**|当前终端的类型|比如 `xterm`、`vt100`，决定了终端怎么显示字符（比如能不能显示颜色、中文，光标怎么移动）。图形界面终端通常是 `xterm`，字符终端可能是 `vt100`。|
|**`LANG`**|系统语言和编码设置|比如 `zh_CN.UTF-8`，决定了程序的语言、日期格式、字符编码。|
|**`HOME`**|当前用户的主目录|比如 `/home/你的用户名`，很多程序会在这里存配置文件（比如 `.bashrc`）。|
|**`LD_LIBRARY_PATH`**|动态库的搜索路径|程序运行时，系统会在这里找 `.so` 动态库。如果你的程序依赖自己编译的库，就需要把库路径加到这个变量里，不然会报 “找不到库” 的错误。|

## 四、举个例子帮你串起来

比如你在终端里敲 `ls` 命令，背后的流程就用到了环境变量：

1. Shell（`SHELL=/bin/bash`）接收到 `ls` 命令；
2. 它去 `PATH` 里的目录里找，在 `/bin` 下找到了 `ls` 程序；
3. 启动 `ls` 进程，把 `TERM=xterm`、`LANG=zh_CN.UTF-8` 这些环境变量传给它；
4. `ls` 根据 `TERM` 知道当前终端是图形界面，用彩色显示文件；根据 `LANG` 用中文输出提示；
5. 显示完结果，进程退出。

---

## 补充：怎么在 Shell 里操作环境变量？

- 查看所有环境变量：`env` 或 `printenv`
- 查看单个变量的值：`echo $PATH`
- 临时设置环境变量：`export PATH=$PATH:./`（把当前目录加到 PATH 里）
- 永久设置：把 `export 变量名=值` 写到 `~/.bashrc` 里，重启终端就生效了。
