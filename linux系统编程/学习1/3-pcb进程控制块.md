## 一、进程控制块 PCB：进程的 “身份证和档案袋”

第一张和第三张图讲的就是 `PCB`，在 Linux 里它的实现是 `struct task_struct` 结构体，相当于操作系统给每个进程建的专属档案袋，里面存了这个进程的所有关键信息。

你可以把它理解成：

- 每个进程一出生，内核就给它发一个 “档案袋”，所有和这个进程相关的信息，全存在这里面。
- 内核管理进程时，根本不是直接操作代码，而是通过这个 `task_struct` 来识别、调度、控制进程。

### 1. 里面存了哪些关键信息？（对应图里的列表）

表格

|信息项|大白话解释|
|:--|:--|
|进程 ID（pid_t）|进程的唯一身份证号，系统里每个进程的 pid 都不一样，`ps` 命令看到的 `PID` 就是它。|
|进程状态|进程现在是在运行、排队等 CPU、还是在等 I/O，内核全记在这里。|
|CPU 寄存器信息|进程被暂停时，CPU 里的寄存器值会被存到这里；恢复运行时再读回来，实现 “断点续跑”。|
|虚拟地址空间信息|进程的代码段、数据段、堆、栈、页表等内存布局，都由这里管理。|
|控制终端信息|进程是从哪个终端启动的（比如你在哪个窗口敲命令运行的程序）。|
|当前工作目录（CWD）|进程现在默认操作的目录，比如你在 `/home/xxx` 运行程序，CWD 就是这个路径。|
|umask 掩码|进程创建新文件时，默认的权限掩码，决定文件的初始权限。|
|文件描述符表|进程打开的所有文件、套接字的列表，`stdin/stdout/stderr` 也在这里面。|
|信号相关信息|进程收到的信号（比如 `Ctrl+C` 发的 `SIGINT`）、信号处理函数，都存在这里。|
|用户 ID / 组 ID|进程的运行身份，决定它能访问哪些文件和资源。|
|会话和进程组|进程所属的 “会话” 和 “进程组”，比如你在终端里运行的所有程序，都属于同一个会话。|
|资源上限（RLIMIT）|进程能打开的最大文件数、能占用的最大内存等限制，防止进程乱占资源。|

这些信息全存在 `/usr/src/linux-headers-xxx/include/linux/sched.h` 里的 `struct task_struct` 中，内核通过这个结构体就能完全掌控一个进程。

## 二、进程状态：进程的 “一生” 怎么变化？

第二张图讲的是进程的 5 种基本状态和它们之间的切换，你可以把进程想象成一个 “任务”，它的一生就在这几个状态里来回切换。

### 1. 5 种基本状态

表格

|状态|含义|大白话场景|
|:--|:--|:--|
|**初始态**|进程刚被创建，正在初始化资源（分配 PCB、内存等）|刚写完代码，`./a.out` 刚敲下去，进程刚被创建出来。|
|**就绪态**|进程已经准备好运行，只差 CPU 分配时间片|你打开了很多程序，它们都在排队等 CPU 调度，随时能运行。|
|**运行态**|进程正在 CPU 上执行指令|你正在用浏览器刷视频，浏览器进程此时就在 CPU 上运行。|
|**挂起态（阻塞态）**|进程主动放弃 CPU，在等其他资源（比如键盘输入、磁盘读数据）|程序里写了 `scanf` 等用户输入，此时进程就会阻塞，等你输入完才继续跑。|
|**终止态**|进程运行结束或被杀死，等待内核回收资源|程序执行完 `return 0`，或者你用 `kill` 命令把它结束了。|

### 2. 状态之间怎么切换？（对应图里的箭头）

- **就绪 → 运行**：CPU 时间片轮到它了，调度器把 CPU 分配给它。
- **运行 → 就绪**：时间片用完了，或者有更高优先级的进程进来抢 CPU。
- **运行 → 挂起**：进程主动放弃 CPU，比如等键盘输入、等网络数据。
- **挂起 → 就绪**：进程等待的资源到了（比如用户输入完了），重新加入就绪队列。
- **运行 / 就绪 / 挂起 → 终止**：进程执行完，或者收到退出信号，进入终止态。

---

## 三、两者的关系：PCB 里存着状态，状态由内核调度

你可以把这两部分串起来理解：

1. 每个进程都有一个 `task_struct`（PCB），里面存了它的 `状态`。
2. 内核调度器就是通过读 PCB 里的状态，来决定下一个该运行哪个进程。
3. 进程状态切换时，内核会修改 PCB 里的状态字段，同时保存 / 恢复 CPU 寄存器信息。

---

## 举个完整的例子帮你理解

比如你在终端里运行一个程序：

1. 你敲下 `./a.out`，内核创建进程，分配 `task_struct`（PCB），设置状态为**初始态**，初始化资源。
2. 初始化完成，状态变成**就绪态**，加入就绪队列排队。
3. CPU 时间片轮到它，调度器把它切换到**运行态**，开始执行代码。
4. 代码里遇到 `scanf`，进程需要等你输入，主动放弃 CPU，状态变成**挂起态**，PCB 里记录下此时的寄存器值。
5. 你输入完按回车，进程收到输入，状态变成**就绪态**，重新排队。
6. 又轮到它运行，状态切回**运行态**，恢复之前保存的寄存器值，从 `scanf` 后面继续执行。
7. 程序执行完 `return 0`，状态变成**终止态**，内核回收 PCB 和内存资源，进程彻底消失。
