## 一、孤儿进程（Orphan Process）

### 定义

**父进程先于子进程结束**，导致子进程失去了父进程，就成了孤儿进程。

内核会让系统进程 `init`（现在很多系统是 `systemd`，PID=1）“收养” 这些孤儿进程，成为它们的新父进程。

### 特点

- 孤儿进程是**正常运行的进程**，状态是 `R`（运行态），不是 “坏进程”。
- 它会被 `init` 进程自动回收，不会变成僵尸进程。
- 父进程退出后，子进程的 `getppid()` 会变成 `1`（init 的 PID）。

### 举个例子（orphan.c）

c

运行

```c
#include <stdio.h>
#include <unistd.h>
#include <sys/wait.h>

int main(void)
{
    pid_t pid;
    pid = fork();

    if (pid == 0) {
        while (1) {
            printf("I am child, my parent pid = %d\n", getppid());
            sleep(1);
        }
    } else if (pid > 0) {
        printf("I am parent, my pid is = %d\n", getpid());
        sleep(9);
        printf("----------------parent going to die----------------\n");
    } else {
        perror("fork");
        return 1;
    }

    return 0;
}
```

运行结果：
- 父进程先死，然后子进程一直循环，父进程死了之后，子进程的父亲就变成了init进程。

## 二、僵尸进程（Zombie Process）

### 定义

**子进程已经结束，但父进程还在运行，并且没有调用 `wait()`/`waitpid()` 回收它**。

子进程虽然已经退出，但它的进程控制块（PCB）还留在系统里，状态标记为 `Z`（僵尸态），等待父进程来回收。

### 特点

- 僵尸进程**已经终止，不占用 CPU 资源**，但会占用少量内存（PCB）。
- 无法用 `kill` 命令直接杀死，因为它已经 “死了”。
- 父进程如果一直不回收，它会一直留在系统里，直到父进程退出。

### 举个例子（就是你之前的 zoom.c）

c

运行

```c
#include <stdio.h>
#include <unistd.h>
#include <sys/wait.h>

int main()
{
    pid_t pid = fork();
    if (pid == 0) {
        printf("---child, my parent= %d, going to sleep 10s\n", getppid());
        sleep(10);
        printf("-------------child die--------------\n");
        // 子进程执行完这里就退出了
    } else if (pid > 0) {
        // 父进程死循环，不回收子进程
        while (1) {
            printf("I am parent, pid = %d, myson = %d\n", getpid(), pid);
            sleep(1);
        }
    }
    return 0;
}
```

运行结果：

1. 10 秒后，子进程打印完就退出了
2. 父进程还在循环运行，不回收子进程
3. 用 `ps aux` 查看，会看到子进程的状态是 `Z+`（僵尸）

## 三、孤儿进程 vs 僵尸进程 对比

表格

|特性|孤儿进程|僵尸进程|
|:--|:--|:--|
|状态|正在运行（R）|已经终止（Z）|
|父进程|父进程先退出，被 init 收养|父进程还在运行，未回收子进程|
|资源占用|占用正常进程资源|只占用少量 PCB 内存，不占 CPU|
|影响|无危害，系统会自动处理|少量内存泄漏，大量僵尸会影响系统|
|kill 能否清除|可以正常 kill|无法直接 kill，只能通过父进程处理|

## 四、如何清除僵尸进程？

### 方法 1：父进程调用 `wait()`/`waitpid()` 回收（推荐）

在父进程中主动回收子进程，这是最规范的做法：

c

运行

```
// 阻塞回收，父进程会等子进程退出
wait(NULL);

// 非阻塞回收，父进程可以继续做自己的事
waitpid(pid, NULL, WNOHANG);
```

### 方法 2：父进程退出

父进程一旦退出，所有它的僵尸子进程都会被 `init` 进程自动回收，僵尸状态就消失了。

### 方法 3：杀死父进程（治标不治本）

如果父进程是个死循环程序，你可以 `kill` 掉父进程，这样子进程就会被 `init` 收养并回收，僵尸进程也就没了。

bash

运行

```
# 先找到父进程的 PID（比如 1234）
kill -9 1234
```

⚠️ 注意：这种方法会终止父进程程序，只适合临时处理，不适合正常运行的服务程序。

---

## 五、补充：为什么 kill 命令杀不死僵尸进程？

`kill` 命令的作用是给进程发信号，比如 `SIGTERM`、`SIGKILL`，让进程终止。

但僵尸进程**已经终止了**，它只是一个 “尸体”，不响应任何信号，所以 `kill` 命令对它无效。

只有父进程回收它，或者父进程退出，这个 “尸体” 才会被系统清理掉。
