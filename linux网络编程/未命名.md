g++ server.cpp -o server -Wall -std=c++11


#### 1. `g++`

- **含义**：GNU C++ 编译器（必须用它编译 `.cpp` 文件，`gcc` 是 C 语言编译器，不推荐用来编译 C++）
- **作用**：调用 C++ 编译工具链，完成「预处理 → 编译 → 汇编 → 链接」全流程

#### 2. `server.cpp`

- **含义**：要编译的**源文件**（你的 C++ 服务器代码）
- **作用**：告诉编译器要处理哪个文件

#### 3. `-o server`

- `-o`：output 的缩写，指定**输出文件名**
- `server`：生成的可执行文件名字（你可以改成任意名字，比如 `my_server`）
- **作用**：编译后会生成一个叫 `server` 的可执行文件，而不是默认的 `a.out`

#### 4. `-Wall`

- `-W`：开启警告（Warning）
- `all`：所有类型的警告
- **作用**：让编译器尽可能多地报出潜在问题（比如未使用变量、类型不匹配等），帮你提前发现 Bug

#### 5. `-std=c++11`

- `-std`：指定 C++ 标准版本
- `c++11`：使用 C++11 标准（支持 `constexpr`、`nullptr`、范围 for 等现代特性）
- **作用**：确保代码在不同环境下的兼容性，避免因版本差异导致的编译错误

### 📌 完整流程总结

这条命令的意思是：

> 用 `g++` 编译器，把 `server.cpp` 这个 C++11 标准的源文件，编译成一个叫 `server` 的可执行文件，同时开启所有警告来检查代码问题。

### ✨ 客户端命令同理

bash

运行

```
g++ client.cpp -o client -Wall -std=c++11
```

- 把 `client.cpp` 编译成可执行文件 `client`
- 参数含义和服务器命令完全一致

### 🚀 运行命令

bash

运行

```
./server   # 先跑服务器（./ 表示当前目录下的可执行文件）
./client   # 再开新终端跑客户端
```

- `./`：告诉系统要执行**当前目录**下的文件（Linux 不会默认搜索当前目录，必须显式指定）
- 服务器会先监听端口，客户端连接后发送消息，服务器回复，完成一次 TCP 通信 Demo

### 💡 常见问题补充

- **为什么不能用 `gcc` 编译 C++？**
    
    `gcc` 也能编译 `.cpp`，但不会自动链接 C++ 标准库（比如 `std::cout` 依赖的库），容易报链接错误，`g++` 会自动处理这些，更安全。
- **`-std=c++11` 可以换成更高版本吗？**
    
    可以，比如 `-std=c++14`、`-std=c++17`，只要你的编译器支持，代码也兼容就行。
- **`-Wall` 必须加吗？**
    
    强烈建议加，它能帮你发现很多新手容易犯的低级错误，养成好习惯。
