## 一、先看整体流程：客户端和服务器的系统调用对应关系

你图里的流程可以分成 4 个阶段，每个阶段都对应了 TCP 的核心机制：

表格

|阶段|服务器操作|客户端操作|TCP 状态变化|
|---|---|---|---|
|**初始化**|`socket()` → `bind()` → `listen()` → `accept()`（阻塞等待）|`socket()`|服务器：`CLOSED` → `LISTEN`|
|**建立连接（三次握手）**|收到 `SYN` → 回复 `SYN+ACK` → 收到 `ACK`，`accept()` 返回|`connect()` 发送 `SYN` → 收到 `SYN+ACK` → 回复 `ACK`，`connect()` 返回|双方都变为 `ESTABLISHED`|
|**数据传输**|`read()` 阻塞等待数据 → 处理请求 → `write()` 回复|`write()` 发送请求 → `read()` 阻塞等待回复|保持 `ESTABLISHED`，数据通过滑动窗口传输|
|**关闭连接（四次挥手）**|`read()` 返回 0（收到 `FIN`） → 处理完数据 → `close()` 发送 `FIN`|`close()` 发送 `FIN` → 收到 `ACK` → 收到 `FIN` → 回复 `ACK`|客户端：`FIN_WAIT_1` → `FIN_WAIT_2` → `TIME_WAIT`；服务器：`CLOSE_WAIT` → `LAST_ACK` → `CLOSED`|

## 二、核心细节：系统调用和 TCP 报文的对应关系

### 1. 三次握手阶段（对应你图里的步骤 1-3）

- **服务器**：
    
    - `socket()`：创建监听套接字，内核分配文件描述符。
    - `bind()`：绑定 IP 和端口，告诉内核这个套接字要监听哪个地址。
    - `listen()`：让内核进入被动连接状态，准备接收客户端的 `SYN` 请求。
    - `accept()`：内核完成三次握手后，返回一个已连接的套接字给应用层代码。
    
- **客户端**：
    
    - `socket()`：创建客户端套接字。
    - `connect()`：发送 `SYN` 报文，阻塞等待服务器的 `SYN+ACK` 回复，收到后再回复 `ACK`，三次握手完成，`connect()` 返回。
    

### 2. 数据传输阶段（对应你图里的步骤 4-5）

- 客户端调用 `write()` 发送请求数据，内核把数据放到发送缓冲区，通过 TCP 报文发送给服务器。
- 服务器收到数据后，`read()` 从内核接收缓冲区读取数据，处理完后调用 `write()` 把响应数据发送给客户端。
- 客户端收到响应后，`read()` 返回，继续发送下一个请求，如此循环。

### 3. 关闭连接阶段（对应你图里的步骤 6-8）

- 客户端调用 `close()`，内核发送 `FIN` 报文，进入 `FIN_WAIT_1` 状态。
- 服务器收到 `FIN` 后，内核回复 `ACK`，进入 `CLOSE_WAIT` 状态，此时服务器可以继续发送剩余数据。
- 服务器处理完数据后调用 `close()`，内核发送 `FIN` 报文，进入 `LAST_ACK` 状态。
- 客户端收到 `FIN` 后回复 `ACK`，进入 `TIME_WAIT` 状态，服务器收到 `ACK` 后连接完全关闭。

## 三、结合你的 `TcpServer` 代码，这一节的知识点在哪里用？

1. **`Acceptor` 类**：封装了 `socket()`、`bind()`、`listen()` 操作，对应服务器的初始化阶段，和三次握手的前两步。
2. **`TcpServer::start()`**：调用 `accept()` 阻塞等待连接，三次握手完成后，`accept()` 返回新的连接套接字，交给 `TcpConn` 类管理。
3. **`TcpConn::handleRead()` 和 `TcpConn::handleWrite()`**：封装了 `read()` 和 `write()` 操作，对应数据传输阶段，通过 epoll 事件触发，实现异步读写。
4. **`TcpConn` 类的连接关闭逻辑**：当 `recv()` 返回 0 时，说明收到了客户端的 `FIN`，进入半关闭状态，服务器处理完数据后调用 `close()` 发送自己的 `FIN`，完成四次挥手。

## 四、面试高频问题（这一节的考点）

1. **`accept()` 函数什么时候返回？**
    
    - 三次握手完成后，内核会把已建立好的连接放入队列，`accept()` 从队列中取出连接，返回给应用层。
    
2. **`connect()` 函数什么时候返回？**
    
    - 客户端发送 `SYN`，收到服务器的 `SYN+ACK` 后，回复 `ACK`，三次握手完成，`connect()` 返回。
    
3. **`read()` 返回 0 是什么意思？**
    
    - 表示收到了客户端的 `FIN` 报文，客户端关闭了连接，此时服务器进入半关闭状态。
    
4. **为什么服务器要循环调用 `read()` 和 `write()`？**
    
    - 因为 TCP 是面向字节流的协议，一次 `read()` 可能读不完所有数据，需要循环读取直到收到完整请求。
