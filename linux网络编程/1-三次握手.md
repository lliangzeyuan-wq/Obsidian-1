## 一、三次握手的核心流程（3 步）

TCP 是面向连接的协议，三次握手的目的是：

1. 确认双方的发送能力和接收能力都正常
2. 同步双方的初始序列号（ISN），为后续数据传输做准备
3. 协商连接参数（如 MSS、窗口大小）

### 1. 三次握手过程详解

表格

| 步骤        | 方向        | 报文类型                   | 核心作用                                                                              |
| --------- | --------- | ---------------------- | --------------------------------------------------------------------------------- |
| **第一次握手** | 客户端 → 服务器 | `SYN`（同步报文）            | 客户端发送连接请求，携带自己的初始序列号 `ISN(c)`，请求建立连接                                              |
| **第二次握手** | 服务器 → 客户端 | `SYN + ACK`（同步 + 确认报文） | 服务器回复：<br><br>1. 确认收到客户端的 `SYN`（`ACK=c+1`）<br><br>2. 发送自己的初始序列号 `ISN(s)`，请求与客户端同步 |
| **第三次握手** | 客户端 → 服务器 | `ACK`（确认报文）            | 客户端确认收到服务器的 `SYN`，回复 `ACK=s+1`，双方连接正式建立                                           |

- 三次握手完成后，客户端和服务器的连接状态都变为 `ESTABLISHED`，可以开始传输数据。

## 二、结合你的项目代码，三次握手在哪里发生？

你的服务器代码里，三次握手的流程是由操作系统内核自动完成的，对应这几个关键步骤：

1. `socket()`：创建 TCP 套接字，内核分配文件描述符
2. `bind()`：绑定 IP 和端口，告诉内核这个套接字要监听哪个地址
3. `listen()`：让内核进入被动连接状态，准备接收客户端的 `SYN` 请求
4. `accept()`：内核完成三次握手后，返回一个已连接的套接字给你的应用层代码

### 关键细节：

- 你的 `Acceptor` 类里，`listen()` 函数会调用系统调用 `listen()`，让内核开始监听端口。
- 当客户端发送 `SYN` 请求时，内核会自动完成三次握手，你的代码里 `accept()` 函数只是 “领取” 已经建立好的连接。

## 三、三次握手的常见问题（面试高频）

### 1. 为什么是三次握手，而不是两次？

核心原因是**防止已失效的连接请求报文段被服务器接收，导致资源浪费**：

- 假设只有两次握手：客户端发送的第一个 `SYN` 报文段在网络中滞留，客户端超时重发新的 `SYN` 并建立连接，完成后关闭。
- 此时滞留的旧 `SYN` 报文段到达服务器，服务器回复 `SYN+ACK`，建立连接，但客户端此时已经没有请求，服务器会一直等待数据，浪费资源。
- 三次握手通过客户端的第三次 `ACK` 确认，避免了这种情况。

### 2. 三次握手的异常情况

- **SYN 超时**：服务器发送 `SYN+ACK` 后，长时间收不到客户端的 `ACK`，内核会重试几次，超时后释放半连接（对应 `SYN_RECV` 状态）。
- **SYN 洪水攻击**：攻击者发送大量伪造的 `SYN` 请求，服务器回复 `SYN+ACK` 后收不到 `ACK`，半连接队列被占满，导致正常连接无法建立。你的服务器可以通过调整内核参数（如 `tcp_syncookies`）来缓解。
