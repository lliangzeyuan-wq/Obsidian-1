## 一、SQL vs NoSQL 核心对比

表格

|对比维度|SQL（关系型数据库）|NoSQL（非关系型数据库）|
|:--|:--|:--|
|**数据结构**|结构化（Structured）：固定的表结构，行 + 列，必须提前定义 Schema|非结构化 / 半结构化：灵活的存储方式，不需要提前定义 Schema|
|**数据关联**|关联的（Relational）：表之间通过外键关联，支持复杂的 JOIN 查询|无关联的：数据之间相对独立，不依赖外键关联|
|**查询方式**|SQL 查询：标准的 SQL 语言，功能强大，语法统一|非 SQL：各自有自己的查询 API / 语言，不通用|
|**事务特性**|ACID（强一致性）：<br><br>- 原子性 (Atomicity)<br><br>- 一致性 (Consistency)<br><br>- 隔离性 (Isolation)<br><br>- 持久性 (Durability)|BASE（最终一致性）：<br><br>- 基本可用 (Basically Available)<br><br>- 软状态 (Soft State)<br><br>- 最终一致性 (Eventually Consistent)|
|**存储方式**|磁盘存储：数据持久化存储在硬盘，强调安全稳定|多为内存 / 混合存储：很多 NoSQL（如 Redis）优先用内存，追求高性能|
|**扩展性**|垂直扩展：升级单台服务器的 CPU / 内存 / 硬盘，上限有限|水平扩展：通过增加服务器节点实现横向扩容，理论上无上限|
|**使用场景**|1. 数据结构固定（如财务系统、订单系统）<br><br>2. 对数据安全性、一致性要求极高（银行、交易系统）|1. 数据结构不固定（如用户画像、日志数据）<br><br>2. 对一致性、安全性要求不高<br><br>3. 对性能、并发要求高（如社交、电商热点数据）|

## 二、NoSQL 的四大主流类型（图中右侧）

NoSQL 不是单一技术，而是一大类非关系型数据库的统称，常见有 4 种：

### 1. 键值类型（代表：Redis）

- **特点**：最简单的 NoSQL，数据以`key-value`键值对存储，类似大哈希表
- **优势**：读写极快，支持高并发，适合缓存、会话存储、计数器
- **典型场景**：电商商品缓存、用户登录会话、秒杀活动

### 2. 文档类型（代表：MongoDB）

- **特点**：以 JSON/BSON 文档形式存储，数据结构灵活，支持嵌套字段
- **优势**：Schema 动态可变，查询功能丰富，适合快速迭代的业务
- **典型场景**：内容管理系统、用户画像、物联网数据存储

### 3. 列类型（代表：HBase）

- **特点**：按列族存储数据，适合超大规模的海量数据
- **优势**：高可扩展、高可用，适合分布式大数据场景
- **典型场景**：大数据平台、时序数据、日志分析

### 4. 图类型（代表：Neo4j）

- **特点**：以节点（Node）和关系（Relationship）存储数据，天然适配图结构
- **优势**：擅长处理复杂的关系查询（如路径、关联分析）
- **典型场景**：社交网络、推荐系统、知识图谱、风控关系链

## 三、补充理解：不是 “谁取代谁”，而是 “各取所长”

很多人会误以为 NoSQL 是 SQL 的替代品，其实它们更多是**互补关系**：

- 比如一个电商系统：
    
    - 订单、支付这类核心数据，用 SQL 保证 ACID 一致性
    - 商品详情、用户缓存、浏览记录这类数据，用 NoSQL 提升性能和扩展性
