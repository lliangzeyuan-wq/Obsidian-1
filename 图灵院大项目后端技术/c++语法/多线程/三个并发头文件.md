

# C++ 这三个并发头文件详细讲解：`<thread>`、`<mutex>`、`<condition_variable>`

这三个都是 C++11 正式纳入标准库的多线程编程核心头文件，各司其职，下面逐个拆解内部提供的内容、常用类型、典型用途：

## 一、`<thread>`：线程创建与线程管控

专门负责**操作系统线程的封装**，用来新建、操控独立执行的线程

### 内置核心内容

1. `std::thread`类
    - 功能：实例化这个类就可以创建一个新线程，可以传入普通函数、Lambda 表达式、仿函数作为线程入口函数；
    - 常用成员方法：
        - `join()`：主线程阻塞等待子线程运行结束，回收线程资源；
        - `detach()`：分离线程，子线程后台独立运行，主线程无需等待；
        - `joinable()`：判断线程是否还可以执行 join；
        - `get_id()`：获取线程专属 ID；
2. `std::thread::id`：线程 ID 的数据类型，用来区分不同线程；
3. 命名空间`std::this_thread`，内置静态工具函数：
    - `this_thread::get_id()`：拿到当前正在运行的线程 ID；
    - `this_thread::sleep_for(时长)`：让当前线程休眠指定一段时间；
    - `this_thread::sleep_until(时间点)`：休眠直到设定的时刻；
    - `this_thread::yield()`：主动让出 CPU 时间片，调度器可以切换其他线程运行；

### 典型场景

开启子线程做耗时任务、实现并行运算。

```
#include <thread>
#include <iostream>
void work(){std::cout<<"子线程运行\n";}
int main(){
    std::thread t(work);
    t.join();
    return 0;
}
```

## 二、`<mutex>`：互斥锁，解决多线程竞争共享资源问题

mutex 全称 mutual exclusion（互斥），作用是**保证同一时刻只有一条线程访问临界共享数据**，规避数据竞争、脏写问题

### 内置核心类型

1. `std::mutex`：基础普通互斥锁 基础版本，提供`lock()`上锁、`unlock()`解锁方法，手动操作容易忘记释放锁，一般不裸用；
2. `std::recursive_mutex`：递归互斥锁 允许**同一个线程多次重复上锁**，适配递归函数内部加锁的场景；
3. `std::timed_mutex` / `std::recursive_timed_mutex`：超时锁 可以设置等待锁的最长时长，拿不到锁超时之后就放弃阻塞，避免永久卡死；
4. 锁管理 RAII 智能封装（极其常用，自动解锁）
    - `std::lock_guard<std::mutex>`：构造的时候自动上锁，离开作用域析构自动解锁，适配常规场景；
    - `std::unique_lock<std::mutex>`：更加灵活，支持手动解锁、延迟上锁、转移锁所有权；
5. `std::lock`、`std::try_lock`：一次性对多把互斥锁上锁，规避多锁场景出现死锁

### 典型场景

多线程一起修改全局变量、操作同一个容器，加锁保证数据安全：

```
#include <mutex>
std::mutex mtx;
int cnt = 0;
void add(){
    std::lock_guard<std::mutex> lg(mtx);
    cnt++;
}
```

## 三、`<condition_variable>`：条件变量，实现线程等待 + 唤醒机制

搭配 mutex 一起使用，用于**线程间同步协作**：线程可以阻塞等待某个条件成立，其他线程修改条件后唤醒等待的线程，常用来实现生产者消费者模型

### 内置核心内容

1. `std::condition_variable`：最常用版本，只能配合`std::unique_lock<std::mutex>`进行使用； 核心成员函数：
    - `wait(lock, 判断条件)`：释放持有的锁，线程陷入休眠等待；收到唤醒通知之后重新抢占锁、校验条件，条件不满足就继续等待（可以抵挡虚假唤醒）；
    - `notify_one()`：随机唤醒一个处于等待状态的线程；
    - `notify_all()`：唤醒全部等待中的线程；
2. `std::condition_variable_any`：适配任意种类满足锁规范的锁（不限于 std::mutex，自定义锁也可以搭配），通用性更强，性能开销略大；

### 典型场景（生产者消费者）

消费者线程没拿到产品就 wait 休眠，生产者产出产品之后调用 notify 唤醒消费者进行取货。

```
#include <condition_variable>
std::mutex mtx;
std::condition_variable cv;
bool has_goods = false;
```

# 三者分工对比小结

表格

|头文件|核心定位|依赖关系|
|---|---|---|
|`<thread>`|生产线程、控制线程生命周期|独立可用|
|`<mutex>`|互斥上锁，保护共享临界区|独立可用，常配合条件变量|
|`<condition_variable>`|依靠互斥锁实现线程等待唤醒|必须搭配 mutex 才能正常工作|

### 额外实操小贴士

1. 编译使用这三套接口的时候，Linux GCC 编译命令记得加上`-pthread`参数来链接线程库，不然会报链接错误；
2. 使用`condition_variable`的 wait 时务必传入第二个判断条件，用来抵御操作系统带来的虚假唤醒现象。
